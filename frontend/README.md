# Frontend: API-клиент, Auth, Learning, Assessment и Progress UI

## Разделы темы — QIL-041

`/topics/{id}?language=ru|en#section-{section_id}` — единый reader: все Published-разделы, оглавление, текущий раздел и переходы к предыдущему/следующему. Якоря сохраняются при reload и Back/Forward; язык материала сохраняется в URL и независим от теста. Смена языка сохраняет focus на LanguageSelector; переход к разделу фокусирует его h2.

Метод `api.learning.sections()` получает строгий SectionsArticle через существующий typed wrapper; старый `article()` сохранён для совместимости. Пустой/неполный или нарушающий порядок ответ не отображается частично. Тексты выводятся без HTML/Markdown. QIL-043 по отдельному разрешению минимально адаптирует длинный reader: `learning.reading()` получает собственные отметки, у каждого раздела отдельный end-marker, `progress.markSectionRead()` записывает только его. Промежуточный раздел сохраняет частичный прогресс; Topic Read появляется после всех Published-разделов. Pending POST переживает смену языка, отказ GET и повторную загрузку; hidden/0×0/stale marker по-прежнему не учитываются. После ошибки POST нужен явный GET. Read-гейт Test/Practice объясняется по-русски. Отдельное оглавление/reader остаётся QIL-044. [Контракт и переход](../docs/SECTION_PROGRESS_BACKEND.md).

## Completion progress и reset — QIL-035

`/progress`, домашний каталог и sidebar получают проценты из `GET /api/v1/completion-progress/`; браузер не вычисляет веса, порог или среднее. Каталог RU добавляет названия к Published-снимку completion. На странице есть процент темы, Read, статусы «Не пройдено / Неуспешно / Успешно», Published Practice/null, отдельное mastery и доступные correct_count/total_count лучшего теста. Счётчиков попыток API не предоставляет; история и внутренние поля не отображаются.

«Сбросить весь прогресс» открывает native dialog с предупреждением и обязательной галочкой. До подтверждения POST нет; pending блокирует повтор и закрытие dialog. После 200 с generation выполняется GET, только его подтверждённые данные заменяют прежнее отображение. Потерянный ответ сначала требует явного GET, затем допускает явный повтор того же UUID/исходного generation. После подтверждённого POST и ошибки GET повторяется только GET. Ошибки показывают безопасный текст и сохраняют предыдущие значения; потеря/смена session сразу очищает приватный экран.

Сброс уведомляет соседние вкладки без передачи пользовательских данных. Старые draft/end-marker/ID очищаются; только активный reset-контроллер на /progress временно удерживает read-only отображение. Смена пользователя никогда не откладывается ради dialog. Native focus trap, Escape/отмена и возврат фокуса к кнопке проверяются на desktop/mobile. Текущий QIL-035 не реализует Answer/Finish. [Проверки, ограничения и ручная приёмка](../docs/COMPLETION_UI.md).

## Совместимость completion/reset — backend-этап QIL-034

Добавлены публичные типы/строгие decoders и методы `progress.completion()` и `progress.reset(confirmation, requestId, expectedGeneration)`. Отдельные counts не добавляются: `test` представляет один тест, `practice` — ноль или одну задачу. Все шесть существующих учебных POST и reset передают `X-Progress-Generation` из нового GET; Auth POST остаются без него. Generation хранится только в памяти, bootstrap CSRF и `credentials: include` сохранены.

Устаревший generation не обновляется с повтором POST. Поздние приватные GET отбрасываются, reset/неопределённый исход reset блокирует старое автопрочтение; вкладки получают только сигнал без пользовательских данных. Общий экземпляр клиента очищает состояние экрана переходом с перезагрузкой на `/progress`. Новый явный переход к статье допускает новое чтение. Повтор reset требует прежних UUID, тела и исходного generation.

В серверном этапе QIL-034 визуальное расширение Progress отсутствовало. Оно добавлено в QIL-035 выше; legacy GET Progress сохранён для совместимости и Read. Answer/Finish реализован отдельно; единый reader разделов добавляется в QIL-041. [Backend и фактические границы](../docs/COMPLETION_BACKEND.md).

## Practice UI — QIL-030

Реализованы `/topics/{topic_id}/practice` и `/practice-submissions/{submission_id}` с группой practice типизированного API-клиента и строгими runtime decoders. Ссылки со статьи и результата теста появляются только после успешного preview; 404 скрывает вход. Read и любой submitted-тест открывают start на backend. Язык задания первоначально берётся из материала, независимо от языка теста.

Текстовый ответ живёт только в памяти, сохраняется при RU/EN и предупреждает при уходе. Счётчик — 5000 Unicode code points, без HTML required/maxlength и без клиентской нормализации. После submit показаны только публичный контекст и Верно/Неверно. Ответы и ключи не сохраняются в storage/логах. POST uncertainty разрешается GET и только явным повтором замороженного payload; 409 загружает сохранённый результат. Удаление требует подтверждения и CSRF. Mastery и Read не меняются; Published Practice участвует в completion по QIL-033/QIL-034, а QIL-035 обновляет sidebar после результата/удаления. История тестов в UI не возвращается.

После ручного просмотра результат «Неверно» выделяется красным, «Верно» — зелёным. Основная кнопка завершённой работы — «Пройти заново»: существующий start API создаёт новую работу с пустым ответом на языке предыдущей отправки, сохраняя прежний результат. Пока запрос выполняется, повторное нажатие блокируется. При неизвестном исходе нового start автоматического повтора нет; UI предупреждает перед явным новым запуском. Отказ доступа сохраняет прежний результат. Отдельное действие «Удалить результат» остаётся с подтверждением.

Seed существует только в E2E временной PostgreSQL. Backend/API, миграции, package-файлы и зависимости сохранены. Полный ручной прогон — PASS: npm ci, 332 backend/HTTPX-теста и 22 подтеста, 198 frontend unit, type-check/build, 96 Playwright, Django/миграции/pip check и cleanup. Роутер синхронно спрашивает разрешение перед сменой React-экрана; отмена Back сохраняет URL и ввод. Подробности, ограничения и один файл проверки — [PRACTICE_UI](../docs/PRACTICE_UI.md). CI проверяется для точного SHA после публикации; локальный PASS не заменяет результат GitHub Actions.

QIL-016 добавил типизированный клиент, QIL-018 — Auth UI, QIL-019 — материалы и чтение, QIL-020 — тестирование и серверный результат, QIL-021 — прогресс и историю. Контракт взят из [архитектуры](../docs/ARCHITECTURE.md) и сверён с backend routes, views и serializers. Оценивание и вычисление освоения остаются на backend.

## Минимальные слои

- `src/api/types.ts` — публичные DTO: объекты данных, которые разрешено получить из API, и входные ответы на вопросы.
- `src/api/decoders.ts` — проверка входящего JSON во время выполнения. TypeScript сам по себе не проверяет сетевые данные. Неожиданные поля или неверные типы дают `ApiError` с `kind=protocol`, без передачи исходного ответа вызывающему коду.
- `src/api/client.ts` — общий Fetch wrapper, CSRF, sessions и четыре группы методов.
- `src/api/index.ts` — общий экземпляр `api` для React-компонентов; base URL берётся из Vite config.
- `src/auth/` — формы, проверка сессии, локальная валидация, фиксированные маршруты и русские тексты в `texts.ts`. В MVP используется русский UI без переключателя; будущий английский UI не меняет API и независимые RU/EN материалов и тестирования.
- `src/learning/` — каталог, статья, словарь и состояние чтения; `model.ts` управляет загрузкой и запоздалыми ответами. Сетевые запросы и runtime decoders остаются в общем `api`.
- `src/assessment/` — запуск, вопросы, выбор ответов, языки, отправка и результат. `answers.ts` формирует только разрешённые ID; `model.ts` сохраняет точный payload на случай неопределённого исхода submit. Запросы выполняет существующий API-клиент, новые зависимости не добавлялись.
- `src/progress/` — общий процент по Published-каталогу и серверным `mastered`. История из UI не запрашивается; результаты и освоение не пересчитываются.
- `src/ui/` — общий `AppShell` learner-экранов, `LanguageSelector` и правило однократного фокуса заголовка. Навигация и logout используют существующий клиент API.

## Маршруты и формы

| Маршрут | Поведение |
| --- | --- |
| `/` | Защищённая главная со списком Published-тем; гость направляется на `/login` |
| `/register` | Email и пароль; HTTP 201 переводит на `/login`, без автоматического входа |
| `/login` | Только заполненность email/пароля; успех всегда переводит на главную `/` |
| `/session` | GET `auth/me/`, email, ссылка на темы и выход; гость перенаправляется на `/login` |
| `/topics` | Каталог только Published-тем, русский язык по умолчанию |
| `/topics/{topic_id}` | Статья, отметка «Прочитано» и секция словаря темы |
| `/topics/{topic_id}/test` | Независимый язык теста и явная кнопка начала попытки |
| `/attempts/{attempt_id}` | Вопросы текущей попытки либо три агрегата результата; сохранённое название темы показывается отдельно от Result |
| `/progress` | Только общий прогресс: освоенные Published-темы / все Published-темы |

Используется History API без новой router-библиотеки: ссылки имеют обычный `href`, работают Back/Forward, заголовок страницы и клавиатура. После выхода открывается `/login`; `next`/`returnTo` не используются. Вошедший пользователь на `/login` или `/register` переводится на `/`.

`ProtectedGate` проверяет сессию до learner-экранов. Гость направляется на `/login`; после входа всегда открывается `/`. Прямая авторизованная ссылка, reload и Back/Forward продолжают работать. Ошибка сети при проверке сессии не выдаётся за гостя. Регистрация по-прежнему ведёт на `/login` без auto-login.

## Материалы и чтение — QIL-019

Каталог сохраняет порядок API по `topic_id`; словарь — `position`, затем `term_id`. UI не сортирует ID как строки и не получает внутренний статус публикации: Published отбирает backend. Draft и missing дают одинаковое безопасное сообщение по реальному `404 not_found`.

Словарь — секция под статьёй: отдельный маршрут для этого пути не требуется. Заголовки, статья и термины выводятся React-текстом, без исполнения HTML/Markdown. `?language=en` хранит язык материала для reload и Back/Forward; отсутствие параметра означает `ru`. Статья и словарь используют один язык; параметр на Learning-странице не задаёт язык теста. Неизвестный/повторный `language` показывает безопасное UI-сообщение, fallback перевода отсутствует.

GET `progress/` показывает собственную отметку по `topic_id`. `useAutomaticRead` сохраняет её существующим CSRF-защищённым POST, когда конец статьи появился на экране активной вкладки. Кнопки отметки нет; короткая статья, целиком видимая на экране, может сохраниться сразу. Pending блокирует повтор, подтверждённая отметка одна для RU/EN и сохраняет первую дату после reload. При ошибке сначала выполняется явный проверочный GET; неизвестное состояние не становится успешным. Автосохранение не меняет фокус.

`authentication_required` скрывает Learning-данные и возвращает к входу; снятие публикации с `404` при `read` убирает статью. Ответы старой страницы/языка не подменяют новые данные. Предусмотрены loading, пустой каталог, недоступная тема и безопасные ошибки сети/отметки. Backend/API и зависимости не менялись.

Каждый прямой вход в auth-маршрут заново проверяет сессию. Только `403 authentication_required` означает гостя. Ошибка сети или сервера оставляет состояние неизвестным и показывает кнопку повторной проверки; она не маскируется под выход. Запоздалые ответы после смены страницы не восстанавливают устаревшее состояние.

У полей есть labels, подсказки и связанные ошибки; фокус переводится на ошибочное поле или сообщение. Во время запроса поля и submit отключаются, повторная отправка блокируется. UI показывает безопасные русские сообщения по `error.code`, без исходного текста исключения. Дубликат email даёт общую `validation_error`, без раскрытия наличия аккаунта. Прерывание POST не вызывает автоматического повтора.

Пароль регистрации проверяется на минимальную длину 8 символов, числовой/распространённый/похожий на email пароль. Для соответствия Django используется его публичный словарь и Unicode-данные, а не новая библиотека; [описание и лицензия](src/auth/POLICY.md). Сервер остаётся окончательной проверкой. При входе правила регистрации не применяются. Пароль хранится в поле формы и временном запросе; после ответа поле очищается. Пароль, CSRF и session ID не сохраняются в Web Storage и не выводятся в UI или логи.

## Тестирование — QIL-020

Ссылка «Пройти тест» ведёт со статьи на подготовку `/topics/{id}/test`. Язык теста по умолчанию `ru` независимо от статьи; `?language=en` на Assessment-маршруте задаёт только язык теста. Русский UI не переключается. Последний язык посещённой статьи запоминается отдельно в памяти вкладки для ссылки «К статье»; Browser Back сохраняет исходный адрес. После новой загрузки приложения без этой памяти ссылка на статью использует RU по умолчанию.

Только кнопка «Начать тест» вызывает существующий POST `topics/{id}/attempts/` с `{language}` и CSRF. Страница проверяет опубликованность через существующий GET статьи, а POST повторно проверяет её на сервере. Потеря ответа start не даёт узнать созданный ID: автоматического повтора нет, UI предупреждает, что явное «Начать новую попытку» может создать ещё одну незавершённую попытку. Новый endpoint поиска незавершённых попыток не добавлялся.

Экран `/attempts/{id}` загружается через GET `attempts/{id}/`. Он показывает один вопрос за раз в порядке публичных вопросов snapshot, radio для Single-choice и checkbox для Multiple-choice. В QIL-038 панель — «Предыдущий — Ответить — Следующий». Answer подтверждает только текущий вопрос без HTTP/оценки и сразу открывает следующий с фокусом на его заголовке. Без выбора кнопка показывает ошибку и не меняет вопрос. Последний Answer только подтверждает ответ; автоматического submit нет. Защита от устаревшего question ID и второго native click не позволяет пропустить заполненный следующий вопрос или случайно нажать Finish. Доступный status сообщает подтверждение. Изменение/clear снимает только его; неизменившийся выбор не снимает. Смена языка и Back/Forward внутри адреса сохраняют выбранные ID, номер и подтверждения; LanguageSelector явно удерживает focus и в WebKit. После reload/ухода GET восстанавливает вопросы, но локальные ответы/подтверждения/номер сбрасываются. Autosave не добавляется.

«Завершить тест» появляется на последнем вопросе только после всех подтверждений; до этого скрыта. Она отправляет только `{language, answers}`, где каждый вопрос имеет непустые `choice_ids`. Подтверждения не передаются backend. Payload фиксируется перед одним POST; повторные нажатия блокируются. `400 incomplete_answers`, `400 validation_error` и CSRF-отказ показывают безопасный русский текст и сохраняют выбор для явного исправления/повтора. `403 authentication_required` возвращает к входу, `404` одинаково скрывает отсутствующую и чужую попытку. Старые submitted с пропусками сохраняют прежние 200/409. [Контракт и проверки QIL-038](../docs/ANSWER_FINISH.md).

При timeout/network/protocol error или неопределённом серверном исходе UI не придумывает оценку. GET проверяет состояние: сохранённый результат сразу показывается; при ещё незавершённой попытке разрешён только явный повтор исходного зафиксированного payload. Изменять ответы или язык этой отправки нельзя. При `409 attempt_already_submitted` вопросы убираются и загружается сохранённый результат; если GET недоступен, доступна только повторная проверка результата, без нового POST.

Объект Result на том же маршруте содержит только серверные `correct_count`, `total_count`, `percentage`; название темы из SubmittedAttempt показывается отдельно в QIL-026. Процент лишь форматируется, не рассчитывается на клиенте. Вопросы/варианты/выбранные ответы убраны; правильные ответы, ключи и внутренний snapshot не получаются. После reload показывается тот же сохранённый результат. Dashboard и сложная история не входят в QIL-020.

## Общий прогресс и меню — QIL-027 / ручная приёмка

`AppShell` показывает слева Published-темы и общий прогресс; в header расположены главная, прогресс, аккаунт и выход. Текущая тема выделена на статье, тесте и результате. На mobile список раскрывается кнопкой; keyboard focus и `aria-current` сохраняются.

`OverviewContext` разделяет между меню и страницей `/progress` два GET: RU-каталог и собственный прогресс. Общий процент = `100 × mastered_published / total_published`. Используется только серверное освоение; `best_result` и история не нужны для расчёта. При пустом каталоге — 0% и пустое состояние. Процент имеет максимум два десятичных знака, точный порог 80% по-прежнему проверяет backend.

После чтения и submit общий прогресс обновляется автоматически, без сброса DOM меню и фокуса. Сеть/403/404/timeout отображаются явно; ошибка не считается нулевым прогрессом. Истории, дат, языков попыток и счётчиков незавершённых попыток в UI нет. Хранение истории, API-клиент `assessment.history()`, ownership, snapshot и прямой URL результата `/attempts/{id}` сохранены.

## Фокус и навигация — QIL-026

Learning, Assessment, Progress и `/session` используют один `AppShell`: ссылка-бренд на главную, «Темы подготовки», «Мой прогресс», «Мой аккаунт» и выход после подтверждения сессии; после ручной приёмки добавлено левое меню. `aria-current=page` отмечает саму страницу раздела, `aria-current=location` — раздел тем на статье, тесте и результате. Активная ссылка выделяется начертанием и подчёркиванием; палитра и типографическая шкала сохранены. Logout выполняет существующий POST с CSRF; потерянный ответ проверяется GET сессии без автоматического повтора POST.

`LanguageSelector` остаётся в DOM при смене языка статьи и теста, включая загрузку перевода. Фокус остаётся на контроле; текущий вопрос и выбранные ID сохраняются в store попытки. Открытие нового маршрута фокусирует его h1 один раз после загрузки. Переход к следующему/предыдущему вопросу фокусирует вопрос; смена языка этого не делает. Отправка переводит фокус на заголовок результата. Промежуточный loading и Back/Forward по языковому query завершённой попытки не фокусируют результат повторно. Прямые URL, reload и существующие безопасные цели после login сохранены.

Клиентская ошибка формы фокусирует первое ошибочное поле. Для серверных `400 validation_error` используются разрешённые `fields`, если они есть; текущая общая ошибка регистрации без полей и `invalid_credentials` фокусируют первый Email без предположения о существовании аккаунта. Сообщение связано с полем через `aria-describedby`. CSRF/сетевая ошибка фокусирует безопасное сообщение. Пароль не сохраняется в store и очищается после отправки.

Результат показывает `topic_title` и язык из существующего SubmittedAttempt отдельно от трёх полей Result, со ссылками «К статье» и «Посмотреть прогресс». Вопросы, ключи, внутренний snapshot и выбранные ответы после submit отсутствуют. Ссылка на снятую с публикации статью может вернуть прежний безопасный 404; сохранённый результат остаётся доступен владельцу. Новых API нет.

Unit-проверки дополнены правилами focus/navigation/logout и сменой языка без пересоздания Learning store. `tests/e2e/test_focus_navigation.py` использует настоящий Django/HTTP/PostgreSQL: стрелки RU→EN→RU, однократный фокус h1, сохранение radio/checkbox и номера вопроса, active-навигация, topic→test→result→progress, контекст после reload и logout. Размеры — 1280×900 и 390×844. Опциональный `QIL_FOCUS_VISUAL_DIR` разрешает только `.cache/qil026-*` для локальных снимков синтетического контента; CI recordings/artifacts не меняются.

## Общие стили и состояния — QIL-027

`src/tokens.css` — единый набор CSS-переменных: прежняя синяя палитра, контрастные текст и границы контролов, типографика, отступы, радиусы и focus ring. `src/styles.css` применяет их к Auth, Learning, Assessment и Progress. h1 имеет размер 28–36 px, h2 — 20–24 px; карточки используют один радиус 12 px, контролы — 8 px. Новых шрифтов и зависимостей нет.

Компоненты `Button`, `Notice`, `LoadingState` и `EmptyState` находятся в `src/ui`. Основное действие синее, вспомогательное — с контуром. `Button` по умолчанию имеет `type=button`; отправка Auth-формы явно использует `type=submit`. `busy` блокирует действие, добавляет `aria-busy`, подпись процесса и индикатор; обычный `disabled` не объявляется загрузкой. `Notice` различает error (`alert`), success и info (`status`), не меняя фокус самостоятельно. Loading сообщает текст через `status`, декоративный индикатор скрыт от assistive technology. При `prefers-reduced-motion: reduce` вращение отключено. Фокус полей, кнопок и ссылок виден; программный фокус h1 и заголовка вопроса сохраняет поведение QIL-026 без лишней рамки.

Длинная статья ограничена 68ch, имеет межстрочный интервал 1.75 и перенос длинных последовательностей. Исходные абзацы и текст API сохраняются через `white-space: pre-wrap`; HTML не интерпретируется. На mobile карточки имеют отступ 16 px, сводка результата складывается в колонку, навигация переносится без горизонтального скролла. Языки статьи/теста, маршруты, Back/Forward, `aria-current` и focus management не меняются.

`tests/presentation.test.ts` проверяет состояния и контраст используемых цветов; это не полная сертификация доступности. `tests/e2e/test_visual_system.py` проверяет реальные страницы, keyboard focus-visible, busy/disabled, сообщения, empty/error и длинную RU/EN-статью на 1280×900 и 390×844. Длинный материал создаётся только в принадлежащей прогону временной PostgreSQL, без изменения демо-текста. Опциональный `QIL_VISUAL_SYSTEM_DIR` разрешает снимки только в `.cache/qil027-*`; снимаются синтетический публичный контент и пустые формы. По умолчанию снимки не создаются и не публикуются в CI. Политика [CI_REPORTS](../docs/CI_REPORTS.md) сохранена.

## Локальный запуск и SPA fallback

Запустите backend на `127.0.0.1:8000` по [основной инструкции](../README.md), затем из `frontend` выполните `npm.cmd run dev`. Откройте `http://127.0.0.1:5173/topics` либо существующие `/register`, `/login`, `/session`. Прямые `/topics/{topic_id}` обслуживаются тем же SPA fallback Vite dev/preview; `/api` проксируется с сохранением Host/Origin для Django CSRF. Для production preview: `npm.cmd run build`, затем `npm.cmd run preview -- --port 4173`.

По умолчанию proxy использует `http://127.0.0.1:8000`. `QIL_API_PROXY_TARGET` задаёт адрес backend только процессу Vite; E2E использует случайный loopback-порт. Это не `VITE_*` и не публичный API URL. В будущем публичный веб-сервер также должен обеспечить SPA fallback и раздельную маршрутизацию `/api`; публичный deploy здесь не реализуется.

## Четыре группы и реальные контракты

Все пути ниже относительны к `/api/v1/`. Методы возвращают проверенное содержимое `data`; `bootstrap` и `logout` возвращают `void`.

| Группа / метод | HTTP | Путь | Результат |
| --- | --- | --- | --- |
| `auth.bootstrap()` | GET | `auth/csrf/` | CSRF в памяти клиента |
| `auth.register(email, password)` | POST | `auth/register/` | Account, HTTP 201; без автоматического входа |
| `auth.login(email, password)` | POST | `auth/login/` | Account, HTTP 200 |
| `auth.logout()` | POST | `auth/logout/` | HTTP 204 без тела |
| `auth.currentSession()` | GET | `auth/me/` | Account; гость получает `403 authentication_required` |
| `learning.catalog(language?)` | GET | `topics/` | TopicSummary[] |
| `learning.article(topicId, language?)` | GET | `topics/{topic_id}/` | Article |
| `learning.terms(topicId, language?)` | GET | `topics/{topic_id}/terms/` | Term[] |
| `assessment.start(topicId, language)` | POST | `topics/{topic_id}/attempts/` | PendingAttempt, HTTP 201 |
| `assessment.get(attemptId, language?)` | GET | `attempts/{attempt_id}/` | PendingAttempt или SubmittedAttempt |
| `assessment.submit(attemptId, language, answers)` | POST | `attempts/{attempt_id}/submit/` | SubmittedAttempt |
| `assessment.history()` | GET | `attempts/` | SubmittedAttempt[] |
| `learning.reading(topicId, language?)` | GET | `topics/{topic_id}/reading/` | TopicReading |
| `learning.section(topicId, sectionId, language?)` | GET | `topics/{topic_id}/sections/{section_id}/` | SectionArticle |
| `progress.markSectionRead(topicId, sectionId)` | POST | `topics/{topic_id}/sections/{section_id}/read/` | SectionRead |
| `progress.markRead(topicId)` | POST | `topics/{topic_id}/read/` | Legacy Progress только при N=1; иначе 403 section_read_required |
| `progress.current()` | GET | `progress/` | Progress[] |

`language` принимает только `ru` или `en`. В GET он передаётся одноимённым query-параметром, при пропуске действует backend default `ru`. В start/submit язык обязателен в JSON. Язык статьи не хранится глобально в клиенте и не влияет на язык теста. Progress и history не принимают query-параметров языка.

## Настройка и безопасность

`VITE_API_BASE_URL` по умолчанию равен `/api/v1/`; шаблон — `.env.example` в этой папке. Это публичная настройка, Vite включает `VITE_*` в браузерную сборку. Backend-секреты в неё не помещаются. Клиент принимает API того же origin, что и страница; в dev используется существующий Vite proxy.

Каждый запрос использует `credentials: include`, `cache: no-store` и запрещает автоматические redirect. Перед каждым POST выполняется CSRF bootstrap, а токен передаётся через `X-CSRFToken`. Одновременные bootstrap используют один запрос. Токен живёт только в памяти текущего запроса и не возвращается методом `auth.bootstrap()`. Следующий POST получает свежий токен, в том числе после ротации при login.

Пароль передаётся только временным аргументом login/register и в предназначенном для них request body. DTO ответов, клиентское хранилище и ошибки не содержат пароль, hash или session ID. Cookie обрабатывает браузер; клиент не читает их через JavaScript. Правильные ответы и внутренние поля отсутствуют в публичных типах и отклоняются при разборе ответа.

`ApiError` содержит `status`, `code`, `message`, `kind` и необязательные `fields`. HTTP-коды и `error.code` сохраняются. Сообщения `fields` для входных полей нормализуются в массивы строк. Ошибка сети имеет `status=0`, `code=network_error`; неверный контракт — `code=invalid_response`; неверная настройка — `code=invalid_configuration`. Это локальные ошибки клиента, не новые backend-контракты. Raw response, request, headers и исходное исключение не прикладываются. Timeout — 15 секунд на запрос, настраивается при создании клиента. POST автоматически не повторяется.
