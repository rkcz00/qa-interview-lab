# Демонстрационный контент — QIL-024

## Содержание и границы

Набор [qa_interview_demo.json](../tests/fixtures/qa_interview_demo.json) — синтетическая учебная тема «Тест-дизайн API: классы эквивалентности и границы». Она содержит эквивалентные статьи RU/EN, три термина, один Single-choice и один Multiple-choice вопрос, восемь вариантов и переводы каждого текста. Это связный пример подготовки к интервью, а не случайные строки технической factory.

Пример описывает вымышленное поле `quantity` с диапазоном целых 1–100. Он объясняет классы эквивалентности, границы, оракул и проверку отсутствия частичной записи. Упомянутый API корзины не является новой функцией или контрактом QA Interview Lab.

В JSON нет аккаунтов, паролей, cookies, токенов, DB-настроек или персональных данных. Ключи проверки нужны серверному seed и тестам; этот файл нельзя отдавать через learner endpoint или включать во frontend. Learner API сохраняет прежние положительные списки публичных полей. После submit доступны только три агрегата результата.

Этот набор можно использовать для технической демонстрации. Смысловую точность и педагогическое качество обоих переводов перед публичным использованием должен подтвердить человек. Автоматическая приёмка проверяет структуру и поведение приложения и не заменяет такую редактуру.

## Явная безопасная загрузка

[Загрузчик](../tools/load_demo_content.py) не запускается при старте приложения, миграциях или CI. CI выполняет только его тесты в отдельных временных базах. Устанавливать зависимости или создавать `.env` для команды не нужно.

Для локальной демонстрации сначала загрузите существующий `.env` в процесс PowerShell по [README](../README.md#загрузка-настроек-в-новый-powershell), убедитесь, что PostgreSQL работает и миграции применены. Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -B tools/load_demo_content.py --database $env:POSTGRES_DB --confirm-create
```

Команда намеренно создаёт постоянную демонстрационную Draft-тему в указанной локальной базе; запускайте её только там, где хотите оставить эту тему. В QIL-024 команда проверяется в удаляемой временной PostgreSQL, а dev-БД не заполняется автоматически.

Защита загрузчика:

- Обязательны точное имя настроенной базы и `--confirm-create`; фактическое `current_database()` сверяется с ним. Служебная база `postgres` и соединения вне loopback запрещены.
- Используются существующие переменные процесса; `.env` не читается и не изменяется. Настройки и секреты не печатаются.
- Создаётся только новая полная Draft-тема без заданных PK. Загрузка атомарна; при невалидном переводе не сохраняется часть дерева.
- Существующие темы, пользователи, группы, попытки и прогресс не изменяются. Если одно из названий демо уже существует, повтор отклоняется без перезаписи. Параллельные запуски этого seed сериализуются транзакционной блокировкой.
- Успех печатает только статус и ID новой темы. Публикация выполняется отдельно Content Admin после просмотра переводов. Автоматического удаления или ротации секретов нет.

Если ранее созданную тему уже переименовали, не используйте повторную загрузку как обновление: найдите её в Admin и работайте с ней. У loader нет отдельного сохраняемого идентификатора seed и механизма обновления существующего материала.

## Редакторский проход

Content Admin — отдельный staff-аккаунт без superuser и прямых дополнительных permissions; его группа имеет только стандартные права на восемь контентных моделей. Учетную запись и членство создаёт технический администратор по отдельному действию; seed этим не занимается. Пароль задаётся интерактивно и не записывается в fixture.

Откройте `/admin/` на backend. Для ручного создания темы начните с Topic в Draft, затем добавьте TopicTranslation, Term/TermTranslation, Question/QuestionTranslation, Choice/ChoiceTranslation. Родительский select содержит его текущую ревизию. После чужой записи откройте свежую форму: старую нельзя безопасно сохранить повторно.

Проверьте названия, статьи и все переводы; сравните варианты обоих типов вопросов с текстом статьи. Выберите тему в списке Topic и действие «Опубликовать выбранные темы», затем подтвердите текущую ревизию. Неполнота даёт `400 incomplete_content` и откат; устаревшая форма — `409 edit_conflict`. Полный Published можно редактировать при сохранении полноты.

После публикации отдельный learner открывает `/topics`, статью/словарь RU/EN и тест с независимым языком. После перевода в Draft новые чтение/попытки закрыты, прежние история/освоение остаются, начатый тест завершается по прежнему snapshot. Content Admin не может просматривать User, Group, Attempt и TopicProgress или чужие learner-данные.

Воспроизводимые проверки и ограничения приведены в [CONTENT_ADMIN_ACCEPTANCE.md](CONTENT_ADMIN_ACCEPTANCE.md). Публичный deploy и создание реального редакторского аккаунта не входят в эту загрузку.
