# Приёмка Content Admin и демо-контента — QIL-024

## Объём

Проверяется существующий редакторский процесс и его результат в learner UI. Требования взяты из FR-03–FR-13 [PRD](PRD.md), разделов 6.3, 6.4 и 7 [архитектуры](ARCHITECTURE.md) и [QA-стратегии](QA_STRATEGY.md). Продуктовый API, модели, миграции, зависимости и CI workflow не меняются.

Синтетическая тема и команда ручной загрузки описаны в [DEMO_CONTENT.md](DEMO_CONTENT.md). Отдельный необязательный загрузчик создаёт полную Draft-тему; редакторский E2E создаёт тот же набор настоящими формами Admin, не подменяя редакторскую запись вызовами ORM.

## Сквозная матрица

Новый [Playwright-сценарий](../tests/e2e/test_content_admin_acceptance.py) использует production-сборку frontend, реальный Django и PostgreSQL. Редактор и learners работают в отдельных browser contexts.

| Сценарий | Оракул |
| --- | --- |
| Группа редактора | Ровно 32 стандартных permissions восьми моделей; staff без superuser и прямых дополнительных grants |
| Разрешённый Admin | Восемь разделов видны; Topic, все переводы, Term, оба типа Question и Choice создаются через формы с CSRF |
| Запрещённый Admin | User/Group отсутствуют в меню и дают 403 по прямым URL; незарегистрированные Attempt/TopicProgress дают 404; чтение и POST к пользовательским данным запрещены |
| Неполный Draft | Пропущен EN-перевод варианта: `400 incomplete_content`, без изменения статуса, revision, дерева и audit log |
| Полный Draft | После добавления перевода восемь моделей содержат 1/2/3/6/2/4/8/16 записей соответственно; публикация даёт Published и одну новую revision |
| Learner UI | Русский каталог, статья/словарь RU/EN, независимый язык теста, radio/checkbox и серверные агрегаты; публичные ответы ограничены разрешёнными полями |
| Published и конфликт | Две формы одной revision: первая полная правка сохраняется, вторая получает `409 edit_conflict`; первая версия остаётся |
| Published и неполнота | Удаление текста статьи даёт `400 incomplete_content`, включая откат названия, revision и audit log |
| Изменение ключа и Draft | Живой MC-ключ меняется через Admin с сохранением полноты, тема снимается с публикации; новые статья/словарь/read/start дают 404 |
| Старый snapshot и прогресс | Публичные вопросы RU/EN начатой попытки прежние; старая попытка получает 100% по исходным ключам; первая отметка, история и освоение сохраняются |
| Ownership | Content Admin и второй learner не читают чужую попытку/прогресс; staff не обходит фильтр владельца |

Вспомогательный [setup/inspect](../tests/e2e/content_admin_data.py) ограничен случайной PostgreSQL-базой fixture. Он создаёт только синтетический staff-аккаунт, принимает временный пароль через stdin и не возвращает его. Проверка БД возвращает лишь counts/status/revision. Все изменения учебного дерева в приёмочном сценарии проходят через настоящий Admin. Внутренний snapshot не извлекается: используются прежние публичные проекции и независимо ожидаемый результат после изменения живого ключа.

## Изоляция и безопасная диагностика

Используются существующие [fixtures](../tests/e2e/conftest.py) и HTTPX/TCP harness. Собственная случайная база создаётся и мигрируется перед прогоном. Окончание сценария удаляет только зарегистрированную им тему и её тестовые попытки/прогресс. Завершение fixture закрывает browser contexts, backend/Vite-процессы и удаляет только свою базу, включая обычное падение теста. Dev-БД и Docker volumes не очищаются.

Секреты поступают в процессы из существующего `.env` без его изменения; ключ Django и данные тестовых аккаунтов временные. Пароли/CSRF/session, правильные ключи и внутренний snapshot не печатаются. Trace/HAR/video/auth state и screenshots редакторских форм не записываются. Сохраняется [политика безопасного JUnit](CI_REPORTS.md), workflow не расширяет upload-пути.

## Проверки

Направленный E2E редактора и шесть PostgreSQL-тестов загрузчика — PASS. Они подтверждают создание Draft, защиту от повторного seed/чужой базы, откат неполного перевода и реальную CLI-команду. Полный backend regression: 227 тестов, включая HTTPX/TCP, без пропусков — PASS. Полный Playwright: 60 тестов (59 прежних и один редакторский), без пропусков — PASS. Frontend: `npm ci`, 130 unit-тестов, type-check и production build — PASS. Django checks, применение миграций в проверочной базе, `migrate --check`, `makemigrations --check`, `pip check`, Python syntax, YAML/Markdown/локальные ссылки, проверка секретов и `git diff --check` — PASS.

Временные PostgreSQL-базы, собственные backend/Vite/browser-процессы и временные файлы очищены. `.env` и шесть ранее существовавших untracked `check-*.py` сохранены. Workflow, lock-файлы, продуктовый код/API и прежние тесты не менялись; E2E fixtures только расширены для изолированного редактора и безопасных проверок counts. Новый CI run проверяется после разрешённого commit/push и фиксируется в итоговом отчёте QIL-024, без второго commit для записи URL.

Для повторного запуска загрузите существующее окружение процесса по [README](../README.md#загрузка-настроек-в-новый-powershell), соберите frontend и используйте существующий Chromium:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = (Resolve-Path '.venv\ms-playwright').Path
.\.venv\Scripts\python.exe -B -m pytest -q backend/apps/learning/tests/test_demo_content.py
.\.venv\Scripts\python.exe -B -m pytest -c tests/e2e/pytest.ini tests/e2e/test_content_admin_acceptance.py -q --tb=short --show-capture=no
```

Полная регрессия выполняется заменой файла на `tests/e2e`; backend — обычным `python -m pytest` из корня с проектным Python. Не используйте `--reuse-db`, не удаляйте volumes и не указывайте общую dev-БД как тестовую.

## Предел приёмки

Это техническая сквозная проверка редакторского сценария, а не утверждение о проведённом человеком ревью. Смысловая проверка RU/EN перед публичной публикацией остаётся открытой; непустые переводы и успешные тесты не доказывают их педагогическое качество. Публичный deploy, реальный Content Admin аккаунт и backup не создаются. Результат GitHub Actions подтверждается отдельно для опубликованного SHA; локальный PASS не подменяет CI.
