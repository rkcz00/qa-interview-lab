# Автоматизированная E2E-приёмка — QIL-022

Это приёмка пользовательского пути на тестовом контенте, а не подтверждение качества учебных материалов или публичного deploy. Источники правил: [PRD](PRD.md), [архитектура](ARCHITECTURE.md), [QA-стратегия](QA_STRATEGY.md), [backlog](BACKLOG.md).

## Реальная связка и изоляция

Playwright открывает production-сборку React через Vite preview. Запросы проходят существующий same-origin proxy к настоящему Django и PostgreSQL 17.11. Успешные API-ответы в новых приёмочных тестах не подменяются. Существующий HTTPX/TCP harness проверяется полным backend-прогоном.

Используются [E2E fixtures](../tests/e2e/conftest.py): собственная случайная база, миграции и два процесса на свободных loopback-портах. Синтетические пользователи, темы и попытки не попадают в dev-БД. При завершении, включая обычное падение теста, закрываются browser contexts и процессы, удаляется только база текущего прогона. Fixture контента меняет и удаляет только созданные ею topic IDs.

Операция `revise_draft` разрешена только для принадлежащих fixture Draft-тем в её временной базе. Она изменяет публичные переводы через существующую транзакционную операцию с проверкой revision. Это позволяет проверить, что ранее начатая попытка продолжает выдавать прежние RU/EN-вопросы и варианты, не читая внутренний snapshot.

## Матрица пользовательского пути

Основной файл — [test_mvp_acceptance.py](../tests/e2e/test_mvp_acceptance.py). Четыре прохода проверяют пары языка статьи/теста `ru/ru`, `ru/en`, `en/ru`, `en/en`; desktop использует ширину 1280, mobile — 390. Пятый сценарий проверяет снятие публикации, последующее редактирование Draft и изоляцию второго пользователя.

## Повторный запуск

Нужны работающий локальный PostgreSQL, проектная `.venv`, установленные по lock зависимости и уже согласованный Chromium в `.venv/ms-playwright`. Несекретные настройки и существующие локальные секреты должны быть загружены в окружение процесса по [README](../README.md); не печатайте их. CI передаёт только временные настройки собственного service container.

Из корня проекта после подготовки окружения:

```powershell
npm.cmd --prefix frontend ci --no-audit --no-fund
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
$env:PLAYWRIGHT_BROWSERS_PATH = (Resolve-Path '.venv\ms-playwright').Path
.\.venv\Scripts\python.exe -B -m pytest -q --tb=short --show-capture=no
.\.venv\Scripts\python.exe -B -m pytest -c tests/e2e/pytest.ini tests/e2e -q --tb=short --show-capture=no
```

Для направленного прогона новых сценариев замените папку в последней команде на `tests/e2e/test_mvp_acceptance.py`. Не используйте `--reuse-db`, общий dev database или очистку Docker volumes.

## Диагностика и границы

Пароли, CSRF/session cookies, внутренний snapshot и серверные ключи не печатаются. Проверки JSON используют разрешённые списки полей и безопасные сообщения вместо дампа ответа. Trace/HAR/video и auth state не сохраняются. Необязательные локальные screenshots показывают только синтетический прогресс и находятся в игнорируемой `.cache`; формы с паролем не снимаются.

Браузер — существующий Chromium; дополнительные браузеры не объявляются проверенными. Для недоступной только прочитанной темы без завершённой истории API не содержит названия: UI явно показывает ID. Смысл переводов, демонстрационная тема и ручная проверка Content Admin остаются QIL-024; автоматизированные backend-проверки Content Admin сохранены. Публичное размещение не входит в QIL-022.
